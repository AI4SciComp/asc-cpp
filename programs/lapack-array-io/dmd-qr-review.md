# Checked GEDMDQ trajectory analysis

This P09 slice adds checked SGEDMDQ, DGEDMDQ, CGEDMDQ and ZGEDMDQ query/execute
APIs. It retains the pinned Reference-LAPACK3.12.1 implementation, commit
`6ec7f2bc4ecf4c4a93496aa2fa519575bc0e39ca`, tree
`7217db728e4f7ee87dabf545a1a87a3d6cd30e9b`. These are first-party adapters and
resource checks, not copied or modified upstream numerical algorithms. The
single-real QR-factored mathematical failure below prevents full family
acceptance. No numerical tolerance, required case or provider option is changed.

## Source, API and publication contract

The accepted domain is the documented M>=N trajectory F with p=max(N-1,0)
snapshot pairs. The outer native argument check also admits N=M+1, but its
factored-vector branch copies N rows from a MIN(M,N)-row X. That undocumented
extension is not admitted by this API. Rank selectors are -1, -2 or a maximum
1..p, as required by the nested GEDMD and parameter documentation. Residual
estimates require explicit vectors. N=0/1 completes locally with rank0, absent
INFO, and no numeric access or mutation. Positive maximum-rank selectors do
not exist for those empty pair sets.

All seven matrices have independent padded row/column layouts: F m-by-n,
X n-by-p, Y n-by-n, Z m-by-p, B n-by-p and W/S p-by-p. Eigenvalues, singular
values and residuals each have p entries; tau has n entries. All capacities are
required even for inactive output. F alone supplies numeric input. The adapter
stages F and all outputs in live typed caller-owned workspace. Queries read
metadata only, without native queries. Plans bind the provider, scalar, nine
dimensions and sixteen option/layout/tolerance fields. No implicit allocation,
transfer, synchronization or fallback is introduced.

On INFO0/4, F publishes packed QR or explicit Q according to the requested
option, and all n tau coefficients publish. With packed F, these coefficients
and reflectors can be reused through public ORMQR/UNMQR. X publishes k POD
columns. Requested Y publishes the full triangular R; otherwise caller Y is
unchanged. Explicit/POD-factored Z publishes m-by-k; QR-factored Z publishes
n-by-k for lifting by Q. B contains compressed refinement or exact-mode data,
also lifted by Q. Eigenvalues/residuals publish leading k, singular values all
p, and defined W/raw S publish k-by-k. S is overwritten eigensolver state,
not a quotient certificate. Inactive output, tails and padding stay unchanged.

INFO4 publishes complete defined warning output with non-OK numerical status.
INFO2/3 reports nonconvergence and withholds all caller numeric output/rank.
Missing, narrow or invalid INFO/rank is a provider defect with no publication.
Rank must be1..p on native INFO0/4. Report/rank/plan/provider aliases and active
workspace aliases reject before metadata reset. Signature assertions include
six hidden Fortran string lengths. The installed S/C/Z C declarations mark K
const although Fortran defines it as output; a live mutable full-width sentinel
is supplied. Only the test wrapper's intentional writes require a localized
const_cast of that actually mutable object.

The resource proof composes the existing checked GEDMD expressions with the
actual QR prefixes and selected QR-application/explicit-Q queries. Native
integer expressions, scalar query encodings and sufficient capacities remain
separate. Real tau occupies WORK[0:n], singular values start at WORK[n], and
post-QR scratch starts at2*n-1; complex post-QR scratch starts at n and singular
values use RWORK. The tau prefix survives all phases. Spare WORK is capped at
the checked preferred count. Bounds cover M+1, foreign matrix/loop cursors,
nested SVD/eigen arithmetic and selected QR-application query expressions.
Packing/publication uses O(m*n+n*n) additional operations and storage; the
selected provider QR/SVD/eigen routines determine numerical cost. No constant
cost or performance claim is made. Exact four-scalar source identities and
formula review are in `master-continuation-20260910-01/dmdq-source-review-01`.

## Required numerical failure and decision

The direct probe `dmdq-prerequisite-02` executes32 variants per scalar/ABI for
m5,n4 trajectories generated by diag(2,3,0,0,0), or complex diag(2+i,3-i,0,0,0),
starting at [1,1,0,0,0]. Four SVD choices and minimum/preferred workspace give
eight failing single-real JOBS=Y/JOBZ=Q/JOBF=E variants. There is one underlying
single-real fixture and one source cause, not eight independent input systems
or bugs. Each direct probe process runs all four scalars:120 variants pass,
eight fail. Both actual ABIs reproduce the same cause. Probe01 stopped after
LP64; it did not execute ILP64. All historical outputs remain retained.

SGEDMDQ source line703 omits WNTVCQ when requesting vectors from nested GEDMD;
D/C/Z include it. The requested Q*Z vectors therefore use uncomputed scratch
in S. For SVD1 minimum WORK, native INFO=0/K=2 and eigenvalues3,2 coexist with
mode norm-squared55.4138239477/1.71089796129 and operator residual norms
5.9006946294/1.30790053069. The required unit-norm/eigenvector property fails
at the unchanged512-epsilon bound. Actual ASC adapter tests preserve exactly
eight failing assertions in one required test process per profile; the D/C/Z
required processes pass. This is a provider numerical defect, not an ASC
packing discrepancy or an objectively invalid oracle. The precise strategy
choice remains in the [owner packet](owner-decisions.md): an explicitly
approved provider correction or separately named composition is needed. No
silent Q-to-V remapping or changed-provider implementation is authorized.
